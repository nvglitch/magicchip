# 技术文章与用户案例

2026-11-05 按用户要求改版。当前两个栏目都留空，不使用示例新闻、虚构案例或未连接正文的技术文档填充页面。

## 页面与布局

- 资源总览和栏目首屏保留官网原有渐变背景、装饰线、大标题、圆角卡片、蓝底图标、阴影与动画。栏目结构调整不重做这些视觉样式；同行参考仅用于文章列表的信息排列方式。
- 英文入口统一使用 `Customer Case`、`Certifications`、`Articles`。导航下拉菜单使用简短介绍，资源总览卡片单独使用 `cardDescriptions` 中更完整的说明，不共用同一段文字，五语同步。总览页三张卡片后放置与产品页同样式的联系销售框，再进入页脚；不重复展示证书，证书预览和下载仅在 `/downloads` 认证页提供，保留原网址。
- 栏目首屏副标题也单独维护：案例和文章页使用 `heroDescriptions`，认证页使用 `displayIntro`，不得再把导航短句当作页面介绍；三处文案用途分别维护，五语同步。

- 技术文章列表保留 `/tech-docs`，详情使用 `/tech-docs/{id}`。取消处理器、网络、安全、API、用户指南等分类导航。
- 列表参考 Cincoze 技术文章页的信息顺序：封面、日期、标题、阅读全文。官网采用桌面三列、平板两列、手机单列图文卡片，增加摘要，每页最多 9 篇，超过后显示上一页/下一页。
- 用户案例使用 `/case-studies`，详情使用 `/case-studies/{id}`。只有获得许可的真实案例才加入此栏目。
- 旧 `/news` 和原有三篇示例新闻详情永久跳转到同语言的用户案例列表；未知旧文章仍返回 404。`content/news` 只保留历史记录用于识别旧链接，不再作为发布来源。
- 详情模板支持封面、发布日期、更新日期、段落、小标题、项目符号列表、正文图片/图片说明、相关文章及联系入口。文本由 React 转义，不执行正文中的 HTML。
- 导航、页脚、资源卡片、SEO、站点地图与搜索入口已同步。发布的新文章会进入各自列表、详情、站点地图和搜索，草稿不出现在这些结果中。
- 资源卡片按实际发布数量统计。当前两个栏目显示“即将推出”，不再写死“12 篇文章”“48 份文档”；合规下载继续按真实 PDF 数量显示。

## 内容入口

统一数据文件为 `content/articles.json`，当前是空数组 `[]`。新增内容时，将一条文章记录加入数组，不需要修改页面代码。字段参考 `docs/templates/article.json.example`。

| 字段 | 用途 |
| --- | --- |
| `id` | 小写英文、数字和连字符组成的稳定网址标识；同一栏目内保持唯一 |
| `kind` | `technical` 为技术文章；`case-study` 为真实用户案例 |
| `published` | 完成并核对后设为 `true` |
| `date` | 首次发布日期，格式 `YYYY-MM-DD` |
| `updated` | 可选的更新日期，不早于发布日期 |
| `image` | 项目内 `/assets/…` 封面地址，建议 1200 × 750；不要引用同行图片 |
| `translations` | `en`、`de`、`fr`、`it`、`es` 五语内容 |
| 每种语言的 `title` / `excerpt` / `imageAlt` | 标题、摘要、封面替代文字 |
| 每种语言的 `body` | 按顺序排列的正文块 |

正文块可使用：

```json
[
  { "type": "heading", "text": "Section heading" },
  { "type": "paragraph", "text": "Paragraph text" },
  { "type": "list", "items": ["First point", "Second point"] },
  { "type": "image", "src": "/assets/articles/example.webp", "alt": "Image description", "caption": "Optional caption" }
]
```

模板默认 `published: false` 且正文为空，不能直接发布。只有五语标题、摘要、图片替代文字和正文完整、日期有效、图片使用项目内资源的记录才会显示；不完整翻译不回退到英文凑成五语文章。草稿模板存放在 `docs/templates`，准备好后再加入发布数据文件。

真实案例正文通常按“项目需求、约束条件、所用方案、验证过程、结果”组织。没有客户确认的项目结果、数字或客户名称不要填入；当前没有案例，因此先留空。

## 本地验证

1. 检查所有图片已落入 `public/assets/articles/`，正文图片保持原始比例。
2. 运行 `node scripts/test-editorial.cjs`、`node scripts/test-site-search.cjs`、`node scripts/test-analytics.cjs` 和 `npm run build`。
3. 在本地预览检查五语列表/详情、封面、翻页、旧链接跳转、canonical 与 hreflang。`node scripts/test-language-routing.cjs` 可验证语言入口。
4. 检查用户案例与技术文章的数据没有混用，草稿未出现在列表、搜索和站点地图。
5. 只做本地编辑与验证，用户自行通过 GitHub CI/CD 发布。
