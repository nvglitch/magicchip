# 技术文章行文与排版规范

本规范记录用户在 2026-11-06 确认的文章方向。适用于 Articles 栏目的新稿和改写；既有文章的改动仍以每次用户明确的范围为准。当前英文参考稿是 `local-ai-mini-pc-memory`。

## 1. 文章先解决读者的问题

- 文章即使去掉文末产品入口，也应有独立阅读价值。先讲清概念，再解释选择依据、操作方法和常见误区。
- 用具体问题组织文章，例如“显示器和电脑要装在同一位置吗”“串口插头相同为什么仍不能通信”，而不是按自有产品系列组织正文。
- 介绍每种方案的适用条件和代价，不把某一种形态、内存类型或接口数量写成普遍更优。
- 通用说明尽量用普通技术词。术语首次出现时说明含义，区分连接器、电气接口、通信协议和应用软件等不同层次。
- 示例应明确是解释性示例；没有真实项目资料就不包装成客户案例，没有实测就不写性能、兼容性、寿命或可靠性保证。
- 摘要说明文章能帮助读者理解什么，不列自有 SKU，不使用“联系我们获取方案”等销售话术。

## 2. 推荐的叙述顺序

1. 用一到两个自然段交代实际问题及文章要回答的核心问题。
2. 解释必要概念和工作原理。
3. 比较可选方案、限制及适用条件。
4. 给出可执行的方法、检查表或排障思路。
5. 用简短结尾帮助读者把判断依据应用到自己的项目。
6. 正文结束后，再放一个硬件分类入口。

不必为了凑结构固定每篇章节数量。通常 4–7 个主要章节足够；不要把每一句操作说明都升级成小标题。

## 3. 自然段与阅读密度

- 同一观点的因果、解释和例子放在同一自然段。英文通常每段 2–5 句、约 40–100 词，按语义调整，不作为机械字数门槛。
- 不采用连续“一句话一段”。独立的过渡句、列表引导或必要提示可以例外；也不要为了减少滚动把整节压成一个大段落。
- 短步骤用编号列表，注意跨代码块后编号仍然连续。并列检查项用项目符号，不用重复的卡片或大标题。
- 表格用于比较同类信息；列名尽量简短。普通解释保留为段落，不把全文卡片化。
- 保留必要技术信息，通过合并碎段落和调整空白改善长度，不靠删掉关键限制或缩小字号。

## 4. 已确认的视觉规则

| 元素 | 当前约定 |
| --- | --- |
| 顶部 | 沿用深蓝网格背景、白色标题及现有摘要、日期、封面布局 |
| 进入效果 | 保留标题与摘要的文字渐入，并尊重减少动态效果的系统偏好 |
| 正文背景 | 白色阅读区配浅灰页面背景，品牌蓝仅用于少量强调及链接 |
| 正文文字 | 16px，28px 行高；段后约 16px，不统一堆叠 28px 大空白 |
| 主章节标题 | 约 24px、半粗；章前约 40px、章后约 16px |
| 小标题 | 约 20px、中等字重；前约 28px、后约 8px |
| 列表 | 紧凑的普通列表，不加左侧蓝条，不给每组列表套装饰面板 |
| 目录 | 桌面跟随滚动并高亮当前章节；手机可展开；链接落点避开固定导航 |
| 表格/代码 | 在各自容器内横向滚动，不能撑出整页横向滚动条 |

这些是当前模板的阅读基准，并非要求改写其他页面。未经明确要求，不修改全局样式、页头颜色、导航、页尾或其他文章。

## 5. 正文与产品入口的边界

- 科普正文不插入 MagicChip 的型号、产品参数对比、报价、产品推荐卡或询价框。确实需要写具体型号的测试报告或产品应用说明，须另行明确范围。
- 产品说明不能替代原理说明；不能借“举例”反复介绍自有产品。
- 技术事实继续用第三方原厂文档、标准说明和工具文档核对，但来源链接保存在内部资料核对文档中；不自动在公开正文添加 Further reading、参考文献区或第三方厂商链接。
- 模型下载、工具安装等完成文章步骤所必需且用户已经明确要求的功能性外链，按对应任务的授权范围保留，不与资料来源外链混用。
- 自有硬件入口集中在正文结束后的一个简洁 CTA：简短标题、描述、一个按钮，指向对应产品分类。
- 不在 CTA 上方再插入产品参数、型号对比或第二个产品按钮。全站导航、页尾和已有相关文章导航不属于正文产品 CTA。

## 6. 配图和技术事实

- 图片必须解释当前话题，优先使用已有真实照片、官方原图或准确的代码绘制概念图；图注说明读者应观察的内容。
- 不用外部接口照片冒充内存插槽或内部结构图，不生成不存在的硬件细节，不给图中接口附会未确认的模式或规格。
- 官方模型标识等第三方素材保留出处；不得暗示联名或背书。既有封面不因正文改写而自动替换。
- 通用技术事实以原厂文档、工具官方文档或原始标准资料核对；涉及产品参数时还须遵循 `产品册子来源与更新规范.md`。
- 区分一般规律、解释性示例、厂商标称和实际验证结果。接口数量不代表软件集成完成；前面板防护等级不代表整机等级；可加载模型不代表交互速度。

## 7. 文件与验收

- 保留文章 ID、原 URL、canonical 与语言路由。H1、摘要、正文、目录、SEO 和列表摘要应表达同一主题。
- 复用 `ArticleCopy.presentation: 'guide'` 的阅读排版和已有 CTA 结构，不为单篇文章重做网站。
- 按本次范围更新对应语言，其他语言保留已确认的内容，不回退为英文。新界面文案覆盖英语、德语、法语、意大利语和西班牙语，不新增中文网站文案。
- 核对正文不再含销售式产品推荐、数据和图注一致、标题层级正确、目录锚点有效、文末只有一个产品入口。
- 运行现有文章检查与正式构建；桌面和手机实看段落、列表、表格、图片、目录与页头。发现全仓已有检查问题时如实记录，不借改稿扩展到无关修复。
- 记录主要事实来源和修改范围；完成本地编辑与验证，不自动提交、推送或发布。
