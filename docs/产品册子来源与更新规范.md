# 产品册子来源与更新规范

## 固定资料来源

官网产品资料的优先来源为本机目录：

```text
D:\本地资源库\电脑相关\电脑册子归档\ver2
```

递归检查该目录及所有子目录中的 PDF。后续用户不再需要将新册子复制到 MagicChip 的 `public/assets`；该目录下的旧 PDF 仅作为历史资料，不用于判断最新版本。旧导入脚本若仍读取 `public/assets`，使用前须调整为上述来源，不能继续从旧路径导入。

这是一条按用户请求执行的工作规范，不是后台自动监控任务。用户可以直接说“检查册子有哪些变动并添加到官网”。

## 范围与授权

- “检查变动并添加/更新”：先给出简短变动摘要，然后继续完成新增、修改产品的本地实现及验证，不重复询问是否执行。
- “检查一下”或明确要求“先给方案”：输出差异报告，等待用户决定是否修改。
- 2026-10-13 用户将 NAS 主板纳入更新范围。NASD2700、NASN100、NASN150 放入商业产品分类的独立 NAS Motherboards（NAS-MB）分组，明确为主板而非整机。NASJ4125 与 MCSR6N4 按用户本次指示暂缓，不自动新增；其文件仍计入来源总数，单独记录暂缓数量。
- PDF 数量不等于产品数量。需识别同型号重复册子、同册多型号及机箱/配置变体，避免重复上架。
- 保留用户手动 GitHub CI/CD 发布方式，不自动提交、推送或部署。

## 每次检查步骤

1. **确认目录可访问。** 不可访问时报告实际路径与原因，不以空目录处理，不回退到旧册子并声称已经检查最新版本。
2. **统计来源。** 列出 PDF 总数、各分类数量、排除数量和本次范围。非 PDF 新资料可报告，但不直接当作已确认产品册子导入。
3. **计算文件指纹。** 记录相对路径、大小、修改时间及 SHA-256。内容变化以 SHA-256 为准，修改时间只供参考。
4. **区分变化。** 比较上次观察记录和已应用记录，识别新增、内容修改、仅改名/移动、消失及未完成同步的文件。相同指纹的新旧路径可提示为移动或改名，但仍须核对型号。
5. **核对实际内容。** 打开相关册子，对照项目当前产品数据、参数、图片及详情，整理新增型号、修改字段和资料疑点。不能只根据文件名或日期生成产品参数。
6. **执行授权范围内的修改。** 通常新增具体型号详情，更新已有型号参数和图片，保持原有有效网址；已合并的 B 系列按下文的系列页 / Type SKU 规则处理。分类页及顶部菜单沿用系列归并规则，并自然排序；同步搜索索引、SEO/站点地图数据、相关 CMS 内容和适用的资源入口。首页或场景引用受影响时一并更新。
7. **验证并报告。** 检查型号链接、参数来源、图片路径、分组与排序、搜索匹配，运行生产构建；界面变化需做适当页面检查。交付新增/更新清单、待确认事项及验证结果。
8. **更新状态。** 只有某册对应内容已落实或已核实网站无须变化，且验证完成后，才把该册的 `appliedSha256` 更新为已核实的指纹，记录应用时间和对应型号/页面。失败、资料冲突或尚未处理时保留未同步状态。

文件从来源目录消失时，不自动删除网站产品或图片。先判断是否改名、归档或误删；真正下架需用户明确指示。遇到同型号多册互相冲突时，报告冲突并保留待确认状态，可继续处理无争议的其他产品。

## 来源清单与首次使用

清单位置：`docs/brochure-source-manifest.json`。

关键字段：

| 字段 | 含义 |
| --- | --- |
| `sourceRoot` | 固定来源目录 |
| `observedAtUtc` | 本次扫描时间 |
| `relativePath` | 来源目录内的相对路径 |
| `observedSha256` | 最近观察到的文件内容指纹 |
| `appliedSha256` | 已核实应用于网站的内容指纹；空值表示未核实 |
| `excluded` | 是否不在当前上架范围 |
| `status` | 核对/应用状态 |

首次建档记录了 **117 份 PDF，其中 NAS 主板 3 份，范围内 114 份**。首次仅建立来源观察记录，未逐项核对，当时 `observationOnly` 为 `true`，所有 `appliedSha256` 留空。该历史快照保存在 `brochure-history/initial-observation-2026-09-10.json`。

2026-09-11 已执行首次核对及更新：当时 119 份 PDF，范围内 116 份；107 份已建立应用基线，9 份有待确认参数而保留空的应用指纹。另保留 1 份消失文件的历史记录；当时用户要求下架旧裸型号 MCIPCB13，仅保留 A/B 款。详见 [册子更新报告](册子更新报告-2026-09-11.md)。2026-09-30 新版册将 A/B 款并入 MCIPCB13 系列页；该页面不是恢复旧裸型号 SKU，详见 [本次更新报告](册子更新报告-2026-09-30.md)。

**下一次执行更新时，范围内未核实的文件都必须与当前网站核对，即使它与这次观察指纹相同。** 核对后才能建立可信的已应用基线。后续主要处理新增、内容变化及仍未完成同步的文件。

每次扫描必须先保留旧记录用于比较，再写新观察值；不能用新扫描直接覆盖差异依据。已应用指纹不能因重新扫描而自动推进；消失文件的历史记录也要保留用于核对。

## 文件、语言与部署约定

- 外部原始 PDF 和目录只读，不改名、不搬移、不覆盖。
- 网页实际使用的图片等资源仍存入项目，并在内容中保留可追溯的来源信息。
- 不把本机绝对路径作为公开下载链接。确需提供下载时，单独整理可发布的项目资源。
- 网站构建和 GitHub CI/CD 不访问本机资料目录，构建使用已写入项目的内容和资源。
- 官网界面及需求词维护英语、德语、法语、意大利语、西班牙语。项目内部说明可用中文。
- 本规范优先于旧文档中要求“把新册子放到 public/assets”或假设旧册子为最新版的流程说明。

## 图片裁切与型号预览

- PDF 产品图必须应用原有裁切路径和软蒙版，不能直接把底层 XObject 当作正面或背面。`scripts/pdf-product-images.py` 按图像出现位置渲染，保留原裁切。导入脚本需 Python 安装 pypdf、PyMuPDF、pdfplumber、Pillow。
- 分类页矩形按钮预览使用具体详情页首图，去除多余留白并统一为 640×400 的画布，保持产品原始比例。静态图片和来源映射由 `scripts/build-model-thumbnails.py` 生成，更新首图后需重新生成；构建不访问外部册子目录。
- 缩略图脚本支持在预览 URL 后指定本次更新的型号 ID；局部更新保留其他型号及 SKU 的映射，不重置未涉及的预览。
- 顶部 Scenarios 菜单的产品卡片也使用上述统一缩略图，不直接放大留白不一致的原图；保留安全留白，悬停只轻微放大，避免贴边或裁切。
- MCIPC2A、MCIPC2B 使用 MCIPC2 系列详情页，在配置区选择 Type A / Type B；两款的图片和参数分别维护，不能因归并入口而共用机箱图。
